# Database Models Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the `PasswordResetToken` model and ensure all requested models are present and migrated in the database.

**Architecture:** Add a new `PasswordResetToken` model to the Prisma schema with a relation to the `User` model. Run a migration to apply changes to the SQLite database and regenerate the Prisma Client.

**Tech Stack:** Prisma ORM, SQLite

## Global Constraints
- Database: SQLite (via Prisma)
- Relations: User-centric with cascade deletes where appropriate.
- IDs: Use `cuid()` for consistent distributed ID generation.

---

### Task 1: Update Prisma Schema

**Files:**
- Modify: `prisma/schema.prisma`

**Interfaces:**
- Produces: `PasswordResetToken` model in `schema.prisma`

- [ ] **Step 1: Add PasswordResetToken model to schema.prisma**

```prisma
model PasswordResetToken {
  id        String   @id @default(cuid())
  token     String   @unique
  userId    String
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  expires   DateTime
  createdAt DateTime @default(now())

  @@index([userId])
}
```

- [ ] **Step 2: Add relation to User model**
Add `resetTokens PasswordResetToken[]` to the `User` model in `prisma/schema.prisma`.

- [ ] **Step 3: Commit schema changes**

```bash
git add prisma/schema.prisma
git commit -m "feat(db): add PasswordResetToken model"
```
